## 1. 背景与问题

顶栏「项目入口 / 工作区切换器」已有 11 个可切换设计
（`workspace_breadcrumb.py:42 _SWITCHER_MODES`，存档在
`app/config/settings.py:22 _WORKSPACE_SWITCHER_MODES`）：

```
01 classic  02 navigator  03 triple  04 om_capture  05 dual  06 breadcrumb
07 omnibox  08 history     09 scenes  10 instrument   11 locator
```

用户裁定：**11 个全不满意**。根因诊断：每个模式只优化了四个日常职能里的**一个**，
用户实际「四个都要」，于是任何单职能模式都不够；而把四职能并排堆在一个弹层里
（历史尝试）又「乱乱的」（用户 2026-07-13 原话）。

四个职能：

| 编号 | 职能 | 场景 |
|------|------|------|
| job1 | 回上次拍的地方 | 开软件一键回到最近工作区，继续干 |
| job2 | 同项目内切采样点 | 项目固定（如盐城2026），在多个采样点/断面间反复横跳 |
| job3 | 新建即开拍 | 新建项目 / 新采样点，建完马上进去 |
| job4 | 项目多了找得到 | 搜索 / 浏览全部项目定位 |

## 2. 核心设计原则：上下文自适应，不堆砌

第 12 版不把四职能并排堆四块。而是 **按用户此刻处境，只把当前最该干的那一个
职能放大为主区，其余三个降为一行或一个按钮**。四职能始终都在，但视觉焦点永远只有一个。

判据状态由「当前是否已进入某项目 / 是否正在搜索」决定，弹层据此渲染三态。

搜索框始终置顶，是「兜底职能」：任何状态下一打字即进入全局搜索态，盖掉其余内容。

## 3. 三态布局

顶栏永远只显示**一个**当前位置按钮（面包屑，复用 `_compact_chain_text`）。
点击 / `Ctrl+K` 弹出唯一弹层，弹层内容按下述三态之一渲染。

### 态 1 · 已在某项目/采样点内（最常见，约 90%）

```
顶栏「盐城2026 › 日出海湾 ▾」→ 点开:
┌──────────────────────────────────────────────┐
│ 🔍 搜索项目或采样点                            │  ← 置顶, 光标默认在此
├──────────────────────────────────────────────┤
│ ▸ 盐城2026                          切换项目▾ │  ← 当前项目, ▾ 换项目
│   ● 日出海湾   当前 · 42标本                  │  ← ●=当前工作区
│   ○ 月亮湾            · 0标本      [进入]      │  ← job2 同项目一键横跳
│   ○ 潮间带断面A       · 17标本     [进入]      │
│   ＋ 加采样点到「盐城2026」                     │  ← job3 就地新建即进
├──────────────────────────────────────────────┤
│ 最近去过                                       │
│   ↩ 黄海航次›北港岛   2h前 · 17标本            │  ← job1 跨项目回上次(限 3 行)
├──────────────────────────────────────────────┤
│ ＋新建项目              全部项目…              │  ← job3 新建 / job4 浏览全部→项目树
└──────────────────────────────────────────────┘
```

主区 = 「本项目的采样点列表」（job2），因为在项目内时这是 90% 的动作。

### 态 2 · 未进入任何项目（刚开软件 / 新用户）

```
┌──────────────────────────────────────────────┐
│ 🔍 搜索项目或采样点                            │
├──────────────────────────────────────────────┤
│ 继续上次  ↩ 盐城2026›日出海湾  2h·42标本 [进入]│  ← job1 放大为首行
├──────────────────────────────────────────────┤
│ 最近项目                                       │
│   盐城2026    3采样点 · 59标本                 │  ← 聚合到项目级
│   黄海航次    5采样点 · 88标本                 │
│   北部湾      2采样点 · 16标本                 │
├──────────────────────────────────────────────┤
│ ＋新建项目                     全部项目…       │
└──────────────────────────────────────────────┘
```

主区 = 「继续上次 + 最近项目」（job1），因为还没有当前项目上下文。

### 态 3 · 搜索中（搜索框有输入，盖掉一切）

```
│ 🔍 hc|                                         │
├──────────────────────────────────────────────┤
│ 项目匹配                                       │
│   黄海航次   5采样点 · 88标本          [进入]  │
│ 采样点匹配                                     │
│   黄海航次›红礁       · 12标本         [进入]  │
│   盐城2026›黄海滩     · 3标本          [进入]  │
└──────────────────────────────────────────────┘
   ↑↓ 选 · Enter 进 · Esc 关
```

主区 = 全局模糊匹配结果，分「项目匹配 / 采样点匹配」两组（job4）。

## 4. 行信息规格（一眼识别）

每一行统一结构（复用「上次进入 · 标本数」——用户反复要求过）：

```
[状态点] 名称   [相对时间] · [标本数]   [★收藏]  [进入]
```

- 状态点：`●` 当前工作区 / `○` 可进入 / `⊘` 死路径（盘未连接，整行标灰）。
- 死路径处理：**不再是点了才弹「盘未连接」**。当前代码
  （`workspace_breadcrumb.py:886/1072/1275`）用 `Path(item["directory"]).exists()`
  把死路径**过滤掉**；第 12 版改为**保留、标灰、行尾给「重新定位…」**，让用户看得见、能修。
- 标本数：来自 `workspace_index_service`（缓存 `specimen_count`），缓存缺失回退实时扫描；
  取不到时省略该字段，不阻塞渲染。
- 相对时间：来自 recent 项的 `lastOpenedAt`（`project_service.record_recent_workspace`）。
- ★收藏：置顶该行，跨会话持久（存 QSettings / app_config，见 §7）。

## 5. 交互（键盘优先，老手快）

```
点顶栏按钮 / Ctrl+K   → 开弹层, 光标已落在搜索框
打字                  → 实时过滤 → 进入态 3
↑ / ↓                 → 在可进入行间移动选中
Enter                 → 进入当前选中行 (调 _switch_to_recent / _switch_to)
Esc                   → 关弹层
★                     → 收藏/取消收藏, 收藏行置顶
右键行                → 收藏 · 重新定位… · 在项目树中显示
```

搜索匹配（首版）= 对「项目名 + 采样点名 + 相对路径」做大小写不敏感子串匹配。
拼音首字母（打 `hc` 命中「航次」）= **可选增强**：仓库当前无拼音库，若不可用则
自动降级为纯子串匹配，不作为首版硬需求、不新增强依赖。

## 6. 为什么四职能全在又不堆砌

```
在项目内 → 主区=同项目采样点(job2); 最近/新建/全部 各降一行或一按钮
未进项目 → 主区=继续上次+最近项目(job1); 新建/全部 降为底部按钮
任何时候打字 → 全局搜(job4)盖掉一切
＋按钮常驻底部 → job3 永远能新建即进
∴ 焦点永远只有 1 个主职能, 其余三个在场但不抢眼。
```

## 7. 实现落点（只加不改）

- `_SWITCHER_MODES` 追加 `("command", "12  智能指挥台")`；
  `settings.py:22 _WORKSPACE_SWITCHER_MODES` 集合加 `"command"`。
- `refresh()`（`workspace_breadcrumb.py:369`）：`command` 走 `_build_mode_variant`
  分支（现 classic/navigator/locator 单列，其余进 variant）。新增
  `_build_command_variant(chain)`（或在 `_build_mode_variant` 内分派）。
- 弹层 = 现有 `_build_workspace_menu` / `_populate_workspace_menu`
  （`workspace_breadcrumb.py:764/777`）强化：菜单顶部插入 `QLineEdit` 搜索框
  （`QWidgetAction` 承载），下方按三态填充分区。
- 复用现有能力，**不重造**：
  - MRU / 最近：`_recent_workspaces(limit)`（`:1627`）
  - 进入动作：`_switch_to_recent(path, root)`（`:1468`）/ 内部 `_switch_to`
  - 项目→采样点链：`_chain()` / `_variant_values()`
  - 新建：现有「＋新建项目 / ＋加采样点」动作
  - 标本/采样点数：`workspace_index_service`
- ★收藏持久：QSettings key（如 `ui/switcher_pinned_workspaces`，存 resolved path 集合）。
- **旧 11 模式全部保留**：它们是可切换存档（用户可随时切回对比），且遵守项目
  「保留旧代码不删」规矩（`keep-old-code-commented-not-deleted`）。第 12 版**只加不改** 01–11。

## 8. 测试（TDD 契约）

在 `tests/test_workspace_switcher_modes.py` 增 `command` 模式契约（QT offscreen）：

1. `command` 在 `_WORKSPACE_SWITCHER_MODES` 白名单、可被 `_set_switcher_mode` 选中并持久。
2. 态 1：ctx 处于某项目内 → 弹层含「本项目采样点」分区，且含当前工作区（●）与
   至少一个 `[进入]` 兄弟采样点。
3. 态 2：ctx 无当前项目 → 弹层首行为「继续上次」（存在 recent 时），含「最近项目」聚合。
4. 态 3：搜索框输入 → 结果按子串过滤，非匹配项不出现；`Enter` 触发进入选中项。
5. 死路径：recent 含不存在目录 → 该行渲染为标灰 + 「重新定位…」，**不**被过滤掉。
6. 回归红线：01–11 各模式渲染契约不变（既有测试保持绿）。

## 9. YAGNI（首版明确不做）

- 不做封面缩略图墙（方案 C）：占屏、解码慢、老手用不上；看图去项目树卡片视图。
- 不做无限层目录树摊开（方案 B 右栏）：采样点通常 1–2 层，深层交项目树。
- 收藏首版只「★置顶」，不做拖拽排序。
- 拼音首字母搜索为可选增强，不新增强依赖。

## 10. 验收标准

- 切到 `command` 模式后，在项目内点顶栏按钮：一屏内可完成 job1/2/3/4 任意一个，
  同项目切采样点 ≤1 次点击（不含开弹层）。
- 未进项目开软件：首行即「继续上次」，一键回到最近工作区。
- 打字即搜到任意项目/采样点，Enter 直达。
- 死路径可见且可重新定位，不再点了才报错。
- 01–11 旧模式行为不变，可随时切回。
