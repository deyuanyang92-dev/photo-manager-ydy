# v0.54 基线 → v0.55 架构审计与等价重构方案

审计日期：2026-07-10

## 约束

`v0.54` 是冻结基线；优化结果发布为 `v0.55`，不覆盖基线 tag/Release。

本轮是**等价重构**，不是产品改版：不新增或删除功能，不改变页面入口、交互、
字段语义、数据库事实、编号规则、照片处理结果和文件安全规则。旧 import 路径保留
兼容入口。不能由同一组行为测试证明等价的改动，不进入 v0.55。

## 当前规模

- `app/`：289 个 Python 文件，约 10 万行。
- `tests/`：176 个测试文件，约 4.9 万行。
- 13 个导航页面，但自然业务边界是 9 个业务模块 + 3 个基础模块；详见
  [`module-map.md`](module-map.md)。
- 最大文件：`project_tree_view.py` 4374 行、`theme.py` 2567 行、
  `collab_view.py` 2383 行、`collab_service.py` 2066 行。
- 最大单方法：`ProjectTreeView._setup_ui()` 825 行。

## 问题分级

### P0：生命周期和可重复验证不稳定

1. 单进程全量测试会被协作网络线程的 Windows 原生 access violation 中断。
2. `test_collab_service.py` 在创建 `QApplication` 前已创建大量 `QObject` 派生服务。
3. 打印执行测试会枚举本机串口/打印设备，单元测试受真实硬件影响。
4. 主窗口测试创建大量顶层窗口但不统一销毁，断言全部通过后进程仍可能原生退出。

**影响：** 无法可靠证明重构前后行为相同，也是发布风险。

**处理：** 测试文件独立进程；Qt 应用先于 QObject；硬件发现注入假实现；每个测试
显式关闭顶层窗口。此处理只改变测试生命周期，不改变产品逻辑。

### P1：职责过度集中

1. `ProjectTreeView` 单类 4287 行，混合目录管理、布局、筛选、汇总、缩略图、导出。
2. `WorkbenchView` 直接扇出到 40 个 app 模块；虽然已有 workflow mixin，主类仍承担
   UI 装配、任务生命周期和跨模块协调。
3. `CollabService` 单类 1961 行，包含状态、网络、同步、项目绑定和 Qt 信号适配。
4. `build_qss()` 单函数 1280 行，主题 token 与生成样式耦合。

**目标：** 大页面只做装配和事件路由；规则进入 Qt-free service；独立面板进入 widget；
后台工作由可关闭的 controller/worker 管理。

**本轮策略：** 不一次性移动大类。只迁移已经独立且有定向测试的叶子模块，旧路径
保留兼容别名。核心大类后续按“一个职责、一个提交、一个测试集”拆分。

### P1：依赖方向存在例外

1. 10 个 service 直接依赖 PyQt6；其中多数是必要的线程/信号适配，但业务规则与 Qt
   适配尚未明确分层。
2. `label_print_executor.py` 反向导入 `app.widgets.print_dialog`，是明确的 service → UI
   依赖例外。
3. 页面/组件直接导入数据库模块或 `sqlite3` 有 9 处。
4. 静态图发现 6 个循环依赖组，涉及 DB migration、项目索引、激活/监控、主窗口/
   设置、分组组件和工作台。

**目标依赖：** `view/widget -> service -> db/file adapter`；Qt controller 只适配信号和
线程；service 不导入页面或组件。

**本轮策略：** 先冻结新增反向依赖；现有例外逐个通过接口注入消除，不在发布前
同时重写打印、协作和工作台。

### P2：异常处理过宽

- 全库共有 699 个 bare/`Exception` 级捕获；工作台主类 39 处、工作台监控 32 处、
  协作页 31 处、协作服务 24 处。
- 部分是 UI best-effort 或兼容旧数据库所需，但日志、降级和真正错误混在一起。

**风险：** 失败被静默吞掉，用户看到“没有反应”，维护者无法定位。

**优化规则：** 文件/DB/网络边界捕获具体异常；可降级路径记录上下文；只允许在
关闭、状态栏和可选增强功能上静默失败。异常收窄必须有故障场景测试，因此不批量
机械替换。

### P2：目录按技术层扁平，业务边界不明显

- `app/services/` 顶层约 80 个模块；项目、标本、标签、分类、协作彼此混排。
- 新开发者难以判断新代码放哪里，容易继续扩大大文件。

**处理：** 保留 `views/widgets/services` 分层，同时在各层按业务子域渐进归档。
本轮已迁移 Qt-free 叶子实现，并保留旧模块别名；详见 `migration-checklist.md`。

### P2：测试存在结构耦合

- 部分测试固定依赖导航下标、具体布局像素或旧编号拆分方式。
- 这类断言会阻碍等价整理，也可能诱导代码退回错误语义。

**处理：** 页面定位使用稳定 `view_id`；编号断言调用权威命名规则；布局只断言关键
结构和可操作性。测试适配当前已确认行为，不改变产品实现。

### P3：交付边界不够干净

- 工作区同时存在产品代码、诊断截图、本机网络脚本和用户项目清单变化。
- GitHub 发布若直接 `git add .`，可能把本机辅助文件带入版本。

**处理：** 发布采用白名单式暂存；构建脚本继续生成空的 `user_projects.json`；发布前
扫描密钥、缓存、截图和本机路径；版本号、Git tag、ZIP 名称三者必须一致。

## v0.55 已完成的等价优化

1. 固化 12 模块地图、目录边界和迁移清单。
2. 迁移 5 个叶子 service 到 `project/specimen/label/collab` 子域，旧路径作为同模块
   兼容别名。
3. 增加兼容性测试，验证旧模块与新模块是同一个对象，包含私有 helper 和 monkeypatch。
4. 提供 Windows PowerShell 5.1 可用的分文件测试器，隔离 Qt/网络/打印原生状态。
5. 修复测试生命周期和真实硬件探测，使回归可重复。
6. 不拆 `project_tree_view.py`、`workbench_view.py`、`collab_service.py` 的核心行为。

## 后续等价重构顺序

1. `ProjectTreeView._setup_ui()`：只抽 UI builder/widget，不动选择、查询和导出规则。
2. 打印：把 UI 对话框适配从 service 移到 controller，并保留同一执行接口。
3. 协作：拆 transport、store、sync coordinator、Qt facade；先加 start/stop 生命周期测试。
4. 工作台：按 monitor/compose/organize/result controller 收口，保留现有信号和动作。
5. 异常：以模块为单位收窄并增加失败场景测试，禁止全库替换。
