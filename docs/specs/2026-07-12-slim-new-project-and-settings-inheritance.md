# 新建项目精简 + 项目设置继承闭环

日期：2026-07-12
状态：已确认（用户逐段拍板）
涉及：`new_survey_project_dialog.py`、`project_scaffold_service.py`、`project_tree_view.py`、
`main_window.py`、`workspace_breadcrumb.py`、`project_settings_service.py`、`metadata_panel.py`、
`workbench_view.py`

## 1. 需求与场景（本次更新的由来，供日后回溯/恢复）

### 1.1 用户原话（2026-07-12）

> 「目前这个设计似乎不好，你可以参考 OM Capture 这个软件设计 —— 就是比如只建立一个项目目录，
>  后续点击这个目录，也可以建立子目录？」
>
> 「就比如我创建了江苏盐城2026这个项目，我可以再创建 2 个实际的工作区，即 2 个断面，进行拍照。
>  江苏盐城只是汇总这两个断面，你可以理解为目录中 2 个子目录。然后我可以在目录中，自由创建子目录。」
>
> 「每个项目、子项目或工作区，可以设计一些采集人、采集时间、坐标、经纬度、拍摄场地等信息吗，
>  方便主界面右侧可以自动读取，减少每次拍照都要填写？」
>
> 「拍照过程有可能有变化，主界面信息可以修改的，项目中提前的信息可以被临时改动，
>  比如拍照人、鉴定人等，这个些信息会被记录。」

### 1.2 被替换的旧场景（2026-07-12 上午，commit `6d28eb0` / `fdf9a33`）

旧需求是「一步建好项目 + 采样点」：一个对话框里同时填 项目名称 / 建在哪里 / 地区位置 / 年份 /
采集人 / 地区代码 / 采样点多行列表，点「创建」一次性建出项目根 + N 个采样点工作区，并直接进入
第一个采样点开拍。

**旧设计为什么长这样**：项目根是「容器」（`_data/region.json`，不是拍照工作区），而
`ProjectSettingsDrawer` 只挂在**工作台**上、工作台又要求当前是工作区 —— 于是项目根的设置
（采集人 / 地区代码 / 默认坐标）**根本没有 UI 可以编辑**。那个塞满字段的对话框是设置项目级
默认值的**唯一机会**，所以它必须一次问完。

**旧设计为什么被否**：用户在开工第一步就要想好全部采样点、还要填 6 个字段；而真实工作流是先
建一个项目壳子，边干边往里加断面/站位。

### 1.3 恢复旧行为的方法

旧代码按项目 §7 规矩**以 `#` 注释保留在原处**，不删除。要恢复「一步建好项目 + 采样点」：
反注释 `new_survey_project_dialog.py` 中的 4 个字段 + 采样点多行框及其 `values()` 分支，
`main_window._on_new_survey_project` / `project_tree_view._new_region` 中的 `sites=` 传参与
「建完直接进第一个采样点」分支同样反注释即可。`project_scaffold_service.create_survey_project`
的 `sites` 参数**始终保留**（本次不改），空列表就是「只建项目根」，传列表就是旧行为。

## 2. 目标结构（不变，只是建的时机变了）

```
江苏盐城2026/                 ← 项目 = 容器；只汇总，不放照片
  _data/region.json          ← 「这是容器，不是拍照工作区」标记
  _data/project.db           ← 设置锚点：采集人 / 地区代码 / 默认坐标 / 拍摄场地
  断面A/                      ← 拍照工作区（进入时才初始化）
  断面B/
    站位1/                    ← 任意深度；哪一层进去拍，哪一层才变工作区
```

设置沿目录树**向上继承**（`project_settings_service.get_effective()`，近的祖先赢）：项目根设一次，
所有断面/站位自动继承，不用重填。**本次不动继承机制**。

## 3. 变更清单

### 3.1 新建项目对话框砍到 2 个字段 —— `new_survey_project_dialog.py`

只留 **项目名称\*** + **建在哪里\***（含「浏览…」）。预览文案改为：

```
将创建：江苏盐城2026/
  （空项目；进去后再建断面 / 采样点）
```

移除（§7 注释保留）：地区/位置、年份、采集人、地区代码、**采样点多行框**。
`values()` 相应只返回 `{"parent_dir", "name"}`；`sites` 恒为 `[]`，`meta`/`collector`/`province`
恒为空 —— 调用方不传，服务层默认值兜底。

被移除的字段一律改由 **3.4 的「项目设置」抽屉**事后填。

**服务层 `project_scaffold_service.create_survey_project` 不改**：`sites=[]` 时它本来就只建
项目根 + `region.json` + 设置库，不建 `incoming-jpg/results`。

### 3.2 建完之后落到「项目树」，不再直接进工作台

项目根是容器，进不去。两个入口（顶栏 `main_window._on_new_survey_project:1063`、项目树
`project_tree_view._new_region:4460`）共用同一条落点逻辑：

1. `ctx.settings.project_tree_root = 新项目根`
2. 跳到「项目树」页，树里选中新项目
3. 提示：「项目已建好。点『+ 新建子目录』添加断面 / 采样点；右键项目 →『项目设置』可填采集人、
   地区代码等，下面所有采样点自动继承。」

旧的「建完直接 `enter_workspace(res["sites"][0])` 进工作台」分支 §7 注释保留。

### 3.3 自由建子目录（任意层、空壳）—— `project_tree_view.py`

`_new_subfolder()`（`project_tree_view.py:4538`，纯 `mkdir`，**不**初始化为工作区）行为**保持不变**
—— 这正是「自由搭目录、只有真正进去拍的那层才变工作区」所需要的（中间层 `断面A/` 不会被误建成
拍照点）。

只改**可发现性**：项目树工具栏加一个显眼的 **`+ 新建子目录`** 按钮（现在只藏在右键菜单和
「更多 ▾」里）。选中哪个节点就建在它下面，没选就建在项目根下。复用 `_new_subfolder`，不新写逻辑。

### 3.4 项目根的「项目设置」入口（**本次改动的前提条件，不是可选项**）

项目树 **右键项目节点 →「项目设置…」**，打开同一个 `ProjectSettingsDrawer`，作用在**项目根的
db** 上（`open_project_db_private(root, create=True)`，用完 `close()` —— 跨工作区写完立刻放锁，
Windows 上不放锁会锁住文件夹）。

抽屉本身**不改**，六个 tab 复用：概览（拍摄位置/采集地点/年份）、人员（采集人/拍摄人/鉴定人）、
编号字段（地区代码/样地/站位 + 默认经纬度/地理区）、存储、TIFF 元数据、打印。

没有这个入口，3.1 砍掉的字段就永远设不了 —— 这是整条链路的必要环节。

### 3.5 顶栏：只改文案 + 一个空档态

`workspace_breadcrumb.py` **已经是 OM Capture 式路径条**（`根 / 断面A / ◀ 📁 B2 ▾ ▶`，含历史
前进后退），进了工作区就显示「照片正在存到哪」。**本次不重做顶栏。**

两处小改：

- 下拉菜单项「新建项目（**含采样点**）…」→「新建项目…」。
- **空档态**：刚建完项目、还没建采样点时，没有工作区可显示，面包屑会退回空状态
  `选择工作区 ▾`，用户刚建完项目却看不到项目名。改为：当「有项目根、无工作区」时显示
  `📁 江苏盐城2026（未选采样点）▾`，点开可建/选采样点。

### 3.6 拍摄场地补上预填 —— `project_settings_service.effective_new_specimen_prefill()`

`photo_location`（拍摄场地）已存在于 `project_meta` 设置、抽屉「概览」tab 和 `specimens` 表
（`schema.sql:388`），但 `effective_new_specimen_prefill()` **不返回它** → 右栏新号不预填。
本次补上，返回结构增加 `"photo_location": str`。

**采集时间不做项目级默认**：它是站位级数据（哪天去哪个点采的），已由 `collection_records` 按
`省-样地-站位-日期` 在编号键提交时自动填（`workbench._apply_collection_autofill`）。项目级搞一个
「默认采集时间」只会填错。

### 3.7 拍摄途中换人：手改 → 轻提示 →（可选）写回工作区设置

**现状已满足「临时改 + 被记录」，本节不改这部分**：

- 优先级 `项目默认 < 站位采集记录 < 用户手动/已存`（`metadata_panel.py:66`）。
- 用户一动手改右栏字段（`_on_field_edited:494`）→ 该字段脱离 `_auto_fields` → 此后**任何自动来源
  都不得覆盖它**；项目设置事后再改也冲不掉。
- 改动发 `metadata_changed` → 工作台 autosave → 落到该标本自己的 `specimens` 行，永久留痕。

**本次新增**：手改**只作用于当前标本**，下一个新号又预填回项目默认 —— 拍到一半换了拍摄人，
得一个一个手改。

改为：手动修改 **采集人 / 拍摄人 / 鉴定人 / 拍摄场地** 这 4 个字段后，弹一条**轻提示**（非模态、
可忽略）：

> 以后的新号也用「李四」吗？　[ 只这一个 ]　[ 以后都用 ]

- **只这一个**（默认，忽略提示等同此项）：维持现状，只改当前标本。
- **以后都用**：把该值写回**当前工作区**的设置（`personnel` / `project_meta`），**不写项目根**
  —— 只影响这个断面，不污染整个项目。后续新号即从此值预填。

**为什么不做「会话粘滞」（改了就默默沿用）**：改一个号却悄悄影响后面 50 个，出了错无从追查
是哪一步换的人。轻提示只多一次点击，但「从哪个号开始换的人」是明示且可追的。

**不提示的字段**：经度/纬度/地理区 —— 它们是站位级数据，本来就该由采集记录按站位覆盖，
弹提示只会造成噪音和误写。

## 4. 闭环流程（验收时按这条走）

```
新建项目（只填 项目名称 + 建在哪里）
  → 落到项目树，选中新项目
  → 右键项目 →「项目设置」，填一次 采集人 / 地区代码 / 默认坐标 / 拍摄场地
  → 「+ 新建子目录」建 断面A、断面B（空壳，任意层可再建）
  → 双击 断面A → 首次进入时初始化为工作区 → 进工作台
  → 右栏新号自动带出 采集人/拍摄人/地区代码/坐标/拍摄场地（全部继承自项目根）
  → 中途换拍摄人 → 右栏改 → 提示「以后都用？」→ 选「以后都用」→ 写回断面A 的设置
  → 该标本的值落库留痕；项目根设置不受影响；断面B 仍用项目默认
```

## 6. 红线（不得破坏）

- 项目根**永远不建** `incoming-jpg/` / `results/` —— 它是容器，照片不得堆在项目根。
- 跨工作区写设置一律 `open_project_db_private()` + `finally: close()` —— 缓存连接会持有文件锁，
  Windows 上导致文件夹删不掉/移不动。
- `metadata_panel._auto_fields` 的保护语义（手改过的字段不被自动来源覆盖）不得回退。
- 旧代码 §7 `#` 注释保留，不删除。
