>
> 状态含义：`OPEN` 未做 · `IN-PROGRESS` 在做 · `DONE` 完成并验证 · `DROPPED` 用户明确取消

## R-003 · Windows 卡顿 / 未响应必须修掉 · 状态：IN-PROGRESS (2026-07-12)

**要求**：Windows 上「响应慢、延迟、卡顿、不流畅、未响应」必须深入优化并重新打包。

**已确认根因**（诊断记录，勿重新调研）：
- `collab_service.py` 在 **Qt 主线程**上做同步 `httpx` 请求（`pull_all_specimens_from_session`
  超时 8 s；`_maybe_retry_offline_drafts` 每 15 s 重试；`create_task` 新建标本时 POST 所有 peer），
  一个连不上的 peer 就冻结 UI 数秒。
- `_spawn` 出的 daemon 线程（无 Qt 事件循环）里调用 `QTimer.singleShot` / 主线程 `QSettings`
  → 日志中数百条 `QBasicTimer::start: Timers cannot be started from another thread`。
- `results_column.py` 布局定时器自激振荡（重建→滚动条→列数翻转→重建），每轮同步重解码缩略图。
- `monitor_panel.py` 16 ms 定时器在主线程解码大 TIFF。

**为什么开发时看不见**：WSL2 是 NAT 网络，mDNS 组播出不去 → 发现不到 peer → 阻塞代码根本不执行；
且 `/mnt/*` 上 `QFileSystemWatcher` 收不到 inotify 事件 → 监视面板不重扫。
**只有原生 Windows 才触发。** 见 `PROJECT_MEMORY.md`。

**2026-07-13 启动优化实测更新**：

- 旧 EXE 点击到首窗约 3.5–4.2 秒；新 EXE 同机实测约 1.84 秒。
- Windows 首次默认轻量绘制：关闭大面积阴影/渐变，顶栏使用 Qt 原生图标，不再为小图标加载整套
  `qtawesome` 字体。
- 原生 Windows 只做一次最大化显示，不再 `showNormal → setGeometry → showMaximized`，也不再两次
  `raise/activate/alert`。
- 首屏不再每 150ms 在主线程预导入所有未打开页面；截图保留应用内快捷键，但不在首窗前启动
  `pynput` 系统级键盘钩子。
- 启动分段计时已写入日志，便于后续继续压缩冷启动。
- **遗留**：自动化测试关闭窗口时仍偶发 `QThread: Destroyed while thread is still running`，尚未宣称全修。

## R-006 · 新建项目/工作区流程彻底重构 · 状态：OPEN (2026-07-12)

**要求**：用户对现有「新建项目」设计极度不满（自评 5/100）。心智模型只有两种情况：
1. **项目管理**：建项目（如「北方多样性调查」）→ 下建子目录（「江苏盐城-2026」）→ 内部再有断面 B / 断面 C 等工作区；
2. **直接建工作区**：先干活，后续再移动到某个项目里管理。

要求 agent 帮新手用户评估 + 设计 + 优化，方便管理数据；进入工作台后方便创建项目/工作区。
允许完全重构，可参考旧设计但不受其约束。

**现状痛点**（用户截图）：顶栏下拉「当前 / 本项目内 / 最近使用 / 新建文件夹…」+
新建项目（空目录）/ 新建单个工作区 / 打开文件夹 等多个并列入口，概念混乱。

**本轮设计裁定**：统一成一个「新建」入口，两条主路径同等可见：

- 「创建项目」：项目名 + 保存位置为必填，项目资料可展开填写；可选同时给出第一个拍摄目录路径。
- 「直接创建拍摄目录」：不要求先有项目，后续通过拖放或“归入项目”移动，并连同数据库/照片一起迁移。
- 项目下允许任意层级普通目录；不存在写死的“子目录层/工作区层”。任何目录都可右键设为当前拍摄目录，
  首次进入自动初始化。
- 顶部保存位置选择器负责快速切换；项目树负责完整层级、右键设置、移动和整理，两者共享同一数据源。

## R-007 · 项目与拍摄目录资料必须可设置并继承 · 状态：OPEN (2026-07-12)

**要求**：目录结构不能取代业务资料。创建时和创建后都必须能编辑：

- 项目资料：名称、开始/结束时间、调查目的、负责人、调查区域、说明等。
- 拍摄目录资料：拍摄/采集日期、地点或断面、采集人、拍摄人、设备、备注等。
- 下级拍摄目录默认继承项目资料，允许局部覆盖；标本手工值优先，不能被继承值反向覆盖。
- 独立拍摄目录归入项目时，必须预览继承与冲突，保留原值或由用户明确选择，禁止静默覆盖。
- 创建后可从项目树右键「项目设置 / 拍摄目录设置」随时修改，不得只有创建向导一次机会。

**现状**：已有 `project_settings`、`ProjectSettingsDrawer` 和沿目录树继承机制，可复用；
`project_meta` 已有名称、年份、日期范围、地点和拍摄场地，但缺少明确的「调查目的/项目说明」等字段，
创建入口与设置入口的可发现性仍不足。

**继承优先级**：项目默认 < 最近祖先目录设置 < 当前拍摄目录设置 < 标本手工值。移动独立拍摄目录
进入项目时显示冲突预览，默认保留当前目录已有值，仅继承空字段。

## R-007 · 项目 / 拍摄目录的「资料」必须能设置，不能只有目录 · 状态：OPEN (2026-07-12)

**要求**（用户原话："我在工作区或项目设计一些参数，好像就不支持了…我项目的时间、目的等都无法设置了"）：

创建和管理时，除了目录结构，还要能填两层可继承的资料：

- **项目资料**：项目名称、时间范围（起止）、调查目的、负责人、区域、说明
- **拍摄目录资料**：拍摄日期、地点/断面、采集人、拍摄人、设备、备注

规则：
1. 下级目录**默认继承**上级项目资料，允许逐字段覆盖；
2. 把独立工作区**移入项目时**，先预览「继承哪些 / 保留哪些」，**不得静默覆盖**；
3. 创建后仍能改 —— 项目树右键「项目设置 / 拍摄目录设置」，不是只在创建向导里填一次。

**现状**：`project_settings_service.py` 已存 `projectMeta / personnel / codeLabels / tiffFields / customStorages`
并已实现父→子继承；`project_settings_drawer.py` 是编辑 UI。缺口 = 新建流程里没有填资料这一步，
且资料入口不好找。

## R-006 补充 · 层级不固定死（2026-07-12 修订）

用户/另一 agent 讨论后的修订模型 —— **不强制「项目→子目录→工作区」恰好四层**：

- **保存位置**：磁盘 / 常用根目录
- **项目**：如「航次2026」（带项目资料）
- **文件夹**：**任意层级**（断面/区域/航次…，想套几层套几层）
- **当前拍摄目录**：如「B2」—— 选中即初始化为可拍照的目录（内部才有 `_data/project.db`）

界面上不再强迫用户理解「工作区」这个词；项目树保留普通目录树 + 右键「设为当前拍摄目录」。
